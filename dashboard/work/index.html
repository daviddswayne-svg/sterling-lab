LLM decision support · Enterprise

Agent Marketing Simulator

An LLM tool that evaluates emails, portal pages and designs before launch and returns a forecast, a named A/B winner, element-level fixes and risk flags. Built at Liberty Mutual; described here at the level of architecture and method only.

Asset to evaluate Email, portal page or design
→
Deterministic forecast layer One calibration file is the only source of any number
Qualitative panel 12 seats drawn from 300 synthetic personas; fixed rosters reproduce on rerun
→
Report Forecast, named winner, fixes, risk flags, one falsifiable prediction
Problem
Pre-launch marketing reviews mixed opinion with numbers, and there was no record of whether a past prediction had been right. A model that sounds confident is not the same as one that has been checked.
What I built
Numbers and judgement are kept separate by design: a deterministic forecast layer produces every figure, and a stratified persona panel (built with Anthropic's Claude models) supplies the qualitative read. Governance rules: eight disconnected dashboard exports consolidated into one calibration baseline, a four-level sourcing hierarchy for every printed number, confidence caps, and a rule against naming a winner inside statistical noise.
Result
Validated against six live production A/B tests, with every miss logged permanently. Grading exposed two systematic model biases and one wrong segment assumption, all corrected. Post-fix results are deliberately excluded from the record because they were fit to the same tests.

  • Evaluation & calibration
  • Data governance

Natural language to SQL · Local LLM

ESC Family History Explorer

Three legacy Microsoft Access databases turned into one SQLite database that anyone can question in plain English.

Problem
A family's expedition archive (photos, journals, people, GPS trips) lived in three legacy Access databases that were hard to search, and standard export tools could not decode some of the data.
What I built
Converted the databases to SQLite (about 144K images, 3K people, 6.9K trips) and built a FastAPI service with a local LLM that turns plain-English questions into SQL. Guardrails: read-only SQL validation, query timeouts, result caps, and schema metadata that steers the model away from known mistakes. On top of that: a photo browser, journal magazine, D3 family tree, Leaflet trip maps and a Three.js 3D terrain viewer built on USGS elevation data.
Result
An early 10-question test was too small to trust, so I replaced it with a held-out evaluation of 71 questions, each scored by running the SQL against the database. The current system answers 84.5% of them correctly (mean of three runs), and every miss is logged. Recovered 2,262 historic dates that standard export tools could not decode. The system runs behind a login with identity verification, so there is no public demo.

Multi-agent automation

Bedrock: an insurer run by AI agents

A demo insurance company whose website is planned, illustrated, coded and published each day by a team of autonomous agents, working from real market data.

Market & news data Real prices, 10-year yield, CPI, headlines
→
Content Director Drafts the daily brief and picks the theme
→
Photo Designer Flux render on the M3
Web Developer Page copy; market tiles computed in code
→
Publishing Manager Commits and hot-swaps to production
Problem
Explore how far a small set of specialised agents can run a content operation end to end, and where they need guardrails.
What I built
Four role-specific agents and an orchestrator, run once a day on a local Apple Silicon machine. The Director writes a brief from live market data and news; the Photo Designer renders a hero image with Flux while the Web Developer writes the page copy; the Publisher commits the change and pushes it to the running site. Every figure on the page is computed from fetched data, never written by the model, and a value that can't be fetched shows a dash. If a render fails, the previous image stays. Visitors can replay the latest meeting from the saved log.
Result
A full run takes about 90 seconds, down from several minutes that often ended in a timeout. The most useful lesson came from reading the logs: an early version silently substituted random prices when its data source blocked it, and the model then presented them as live. I removed every fallback that could invent a number and made failures visible instead.

Generative media

Generative film restyling pipeline

Public-domain films repainted frame by frame in the style of a chosen artist, with a review workflow to keep characters consistent.

Frame from Beat the Devil (1953, public domain).

Problem
Off-the-shelf video models drift: faces change and details hallucinate from frame to frame. Restyling a whole film needs consistency, not just one good image.
What I built
A pipeline that replaces each frame with a repainted equivalent using Stable Diffusion 1.5 and SDXL, ControlNet lineart to hold the composition, and custom-trained LoRAs (including a Reginald Marsh SDXL LoRA trained on 74 images). A frame-review workflow catches character drift and hallucination, flagged frames are re-rendered at tuned settings, and optical-flow smoothing evens out the motion.
Result
Several public-domain films restyled end to end in different artist styles. Generative video is a separate strand of the same work: the reel on the home page was made with Gemini, Google Veo 3.1 and ElevenLabs.

  • ControlNet

Voice cloning · Lip-sync · Local AI

AI David: a talking head in my own voice

An AI version of me that answers visitors out loud, in my cloned voice, with a face that moves in time with the words. Everything runs on my own Mac Studio.

Problem
A chatbot on a personal site is only worth having if it sounds like the person and doesn't make things up about them. My cloned voice on ElevenLabs needed a pricier plan, and a video avatar per answer is slow and expensive.
What I built
One portrait re-posed into ten mouth and eye shapes with LivePortrait. Answers come from Gemma 4, limited to a fact sheet I approved; anything outside it gets "you'd have to ask the real David". The voice is cloned from a two-minute recording with Chatterbox (open source, MIT) and every clip carries an inaudible AI watermark. Replies are voiced a sentence at a time and force-aligned letter by letter, so the page can shape the mouth to the sound. Visitors get 20 questions a day.
Result
The voice starts about four seconds after a question, in testing, with no per-use fees. The first lip-sync changed shape on every letter and ran slightly ahead of the audio, which looked frantic. Driving how far the mouth opens from the audio's own loudness, taking the shape from each syllable's vowel, and correcting for speaker latency brought it down to about three changes a second, locked to the sound.

  • LivePortrait
  • Forced alignment
  • Gemma 4 / Ollama

3D in the browser · Three.js

Voxel simulations: a virus and a city

Two interactive voxel worlds that run in the browser: a bacteriophage infecting a bacterium, and Seattle Center with its monorail.

Problem
Explain a process you can't see (how a virus takes over a cell) and model a place people know, in a way anyone can open in a browser and explore.
What I built
The phage is generated voxel by voxel: an icosahedral head, a helical tail sheath, baseplate and legs, and a cut-away bacterium with its wall, membrane, DNA and ribosomes. It plays as a loop in three acts: the phage lands and injects its DNA, takes over the cell (host DNA dissolves, viral DNA copies itself, ribosomes are hijacked), and new phage heads assemble. The Seattle Center model has the Space Needle, MoPOP, working elevators, a monorail on a spline track, several camera views and procedural sound. Both were built with Google AI Studio (Gemini) as the coding partner.
Result
Both run on the home page. An audit of the city model showed why it felt heavy: 213 separately drawn boxes and duplicated voxels meant hundreds of draw calls. A rebuild in progress puts everything on one voxel grid with greedy meshing and voxelizes the Space Needle from a 3D model; in testing it draws the scene in about 120 calls, loads in under a second and holds 60 frames per second.
  • Three.js / WebGL
  • Procedural generation
  • Greedy meshing
  • Google AI Studio

Human + AI music · Hardware synths

A synth band that plays from code

Songs written as code that plays real hardware synthesizers over MIDI. I direct and judge by ear; Claude writes the parts.

Research & brief A band and era, key, tempo, which machine plays what
→
Song script Claude writes the parts as Python on a shared engine
→
Hardware plays it SH-4D, S-1, RA-90 and SP-404 over MIDI
→
Listen, give notes Three to six rounds by ear, then mix, record, master
Problem
I wanted original songs in the style of bands I love, played on real synths rather than software. My first attempt, a local-LLM pipeline that wrote music as ABC notation and converted it to MIDI, produced generic results and I retired it.
What I built
Each song is a standalone script on a shared engine (a clock that handles mixed meters, sections, mix levels) driving a Roland SH-4D, S-1, RA-90 and an SP-404MKII sampler through a Mackie mixer. A songbook collects the rules learned from my feedback (for example: pads must not fade in and out, and any knob movement has to be big enough to hear in a full mix), and finished recordings are mastered automatically to streaming loudness.
Result
More than a dozen songs drafted, with a handful of keepers in the style of The Cure, Depeche Mode, Pink Floyd and Grimes. The lesson: the AI is fast at writing parts, but taste lives in the listening loop, so the process is built around short rounds of real playback and written-down rules.

  • MIDI
  • Roland SH-4D / S-1 / RA-90
  • SP-404MKII
  • Claude
